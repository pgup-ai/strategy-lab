# R10g — signals into positions, and the gate is `trades.csv`

**A design plan, not a pre-registration.** Its acceptance check is an artifact the
repo already trusts: a paper run driven by `ReplayFeed` over a stored range must
reproduce the backtest's own `trades.csv`, trade for trade.

**Charter:** [docs/research/2026-08-03-market-dynamics-engine.md](../research/2026-08-03-market-dynamics-engine.md),
phase R10. Follows R10e/R10f, which closed the census — so the two paths now emit
identical *signals*, and this is the phase that turns a signal into a *position*.

---

## The gap the census never covered

`_extract`'s docstring has said since Phase 1a that the runner gains an
`ExitMode` *"when signals start driving positions rather than being recorded"*.
R10e gave it the mode. The signals are still recorded: there is **no book** in
`src/` — no position tracker, no execution layer, nothing that consumes a
`Signal` and says what the account holds.

So "paper trading" needs two things this program has never built: a book, and a
live feed. **This phase builds the book, and deliberately not the feed**, because
the book has an oracle and the feed does not. `trades.csv` is a frozen artifact,
53 of them are stored, and a book that reproduces one is correct in the only sense
that matters here. A live feed can be diffed against nothing.

---

## The execution semantics, derived rather than assumed

Measured against the installed vectorbt with a controlled 12-bar signal set —
entries at 1, 2 and 6, an exit at 4, a short entry at 8 and a short exit at 10,
`fees=0.001`, `slippage=0.002`, `cash=10_000`, `position_pct=0.95`:

| | rule | evidence |
|---|---|---|
| entry size | `cash × position_pct × scale ÷ close[t]`, off the **raw** close | 94.059406 at close 101 = 10000×0.95/101 exactly |
| buy fill — open long, close short | `close × (1 + slippage)` | 101 → 101.202; 110 → 110.220 |
| sell fill — close long, open short | `close × (1 − slippage)` | 104 → 103.792; 108 → 107.784 |
| fee | `fee_rate × size × fill_price` | 9.519 / (94.059406 × 101.202) = 0.001 |
| repeated same-side entry | **ignored** | bar 2 opened nothing; the bar-1 trade ran to bar 4 |
| short entry while long | closes the long **and** opens the short | two trades at bar 8, both filled at 107.784 |

That last row is the one a book would get wrong by guessing: a reversal needs no
explicit exit signal, and both legs pay the **sell** side because both are sells.

## What gets built

1. **`engine/fills.py`** — a `Fill` record plus the pricing and fee rules above,
   in one place, with the measurements as their justification. Both books use it;
   neither restates it.
2. **`engine/book.py`** — `PaperBook`, consuming the `Signal`s a
   `StrategyRunner` emits and holding a position. Sizing is the engine's own
   (`cash × position_pct × scale`, non-compounding, from *initial* cash), and it
   reads the strategy's per-bar scale the same way the engine does — at entry, and
   never again (R6).
3. **`engine/exposure_book.py`** — the continuous counterpart, consuming
   `ExposureSignal`. The runner has already applied the band, so this converts a
   target *value* into an order the way `from_orders(size_type="targetvalue")`
   does.

Two books rather than one dispatching, for the reason there are two engines, two
runners and three registries: a shared class runs both and says nothing when one
half breaks.

---

## Acceptance checks

1. **A paper run reproduces the backtest, trade for trade.** Driven by
   `ReplayFeed` over a stored perp range, for a strategy under its canonical exit
   mode: same entry bar, exit bar, direction, size and fill price as
   `trades.csv`, on every trade. Asserted against a **real stored report**, not a
   synthetic one.
2. **The reversal case is covered and not merely present.** At least one
   compared trade pair must be a reversal — long closing and short opening on one
   bar — or the check has not exercised the rule most likely to be wrong.
3. **The continuous book matches `run_exposure_backtest`'s orders** over the same
   range: same decision bars, same signed target value.
4. **Non-compounding holds.** Position size is derived from *initial* cash on
   every entry, so a book that has doubled its equity still sizes the next entry
   the same — asserted directly, because compounding is the failure this repo has
   named twice.
5. **Every published figure bit-identical** against a clean `main` worktree. This
   phase adds a consumer; it must not touch what it consumes.
6. **The full suite passes**, both contracts, both safety suites.

---

## What this deliberately does not do

- **No live feed.** `MarketDataFeed` keeps one implementation. The feed is R10
  proper, and it is deliberately the phase *after* the book is proven, so a book
  defect is found against a frozen artifact rather than through a websocket.
- **No order types beyond market-on-close.** The backtest fills at the bar's
  close adjusted for slippage; a book that modelled limits would be reproducing
  something the oracle cannot check.
- **No persistence.** Fills are returned, not stored. What a paper run should
  write is a question for the phase that has a live feed to write *from*, and
  R10a's rule says not to store what a replay can recompute.
- **No funding accrual in the book.** The engine charges carry as a separate
  ledger against held notional; duplicating it here would be a second answer to a
  question `backtests/funding_frame` already owns.

## Then

R10 proper: a live feed behind the same `MarketDataFeed` protocol, driving a book
that is already known to agree with the backtest. Then R11's canary, whose gate —
*"expected vs actual fills"* — only means something once "expected" is something
the book can state.
